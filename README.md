# LingoFlow

Приложение для ежедневного изучения польского: короткий план на сегодня,
связанные уроки, чтение, словарь и подготовка к B1. Интерфейс и поддержка
материалов доступны на русском, польском и английском.

**[Открыть приложение](https://lingoflow-learn.vercel.app)** ·
[План работ](#единый-план-работ) · [История изменений](docs/project-history.md)

## Что можно делать

- Заниматься по дневному плану и сохранять прогресс в аккаунте.
- Изучать темы A1–C2: слова, грамматика, упражнения и тексты с разбором.
- Сохранять слова из чтения и повторять их по SM-2.
- Тренировать письмо, аудирование и речь; слушать файловую польскую озвучку.
- Готовиться к B1: отдельные навыки, учебный прогон пяти частей и письмо
  на 75 минут. История сохраняет агрегаты; самооценка не является баллом экзамена.
- Использовать адаптивный web/PWA, экспортировать данные и управлять аккаунтом.

Живой ИИ-пилот, независимая редактура и подписанный мобильный выпуск требуют
отдельной приёмки. Наличие материалов всех уровней не означает завершённую
независимую проверку их качества.

Оформление использует [единую нейтральную палитру с сине-фиолетовым акцентом](docs/design-system.md)
со светлой и тёмной темой. История выполненного вынесена отдельно.

## Стек и структура

Production — Python/Django, Templates и HTMX в `backend/`.
Supabase предоставляет PostgreSQL, Auth и RLS; GitHub Actions и Vercel — CI и выпуск.
Node.js используется для проверок браузерной логики и операторских инструментов.

```text
backend/                Django: приложение, шаблоны, стили и тесты
supabase/migrations/    последовательные изменения production-базы
mobile/                 отдельный Expo-клиент в подготовке к beta
ops/                    аудит, мониторинг и инструменты восстановления
docs/                   инструкции, приёмки и история
```

## Быстрый запуск

Для новой локальной среды:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
cp .env.example .env.local
python manage.py migrate
python manage.py runserver
```

По умолчанию используется SQLite. Для Supabase Auth задайте локально
`SUPABASE_URL` и `SUPABASE_ANON_KEY`; для PostgreSQL — `DATABASE_URL`.
Секреты не должны попадать в Git. Если среда уже настроена в IDE, используйте
её интерпретатор. [Полная настройка backend и Vercel](backend/README.md).

Перед публикацией:

```bash
cd backend
.venv/bin/python manage.py test
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
```

Изменения Supabase применяются по порядку миграций с проверкой RLS и grants.
[Подробности запуска, маршруты и эксплуатационные ограничения](docs/project-history.md#основные-маршруты).

## Единый план работ

На 22 октября: **6 незавершённых условий широкого запуска и 10 отложенных
направлений**. Технически выполненное перечислено отдельно: оно не заменяет
независимую проверку, реальные наблюдения и решения владельца.

**Где сейчас нужна помощь:** сначала выбрать редактора трёх пилотов и
учеников для PA-04. Параллельно владелец может согласовать юридические данные,
одно тестовое уведомление и место внешнего backup. Для beta нужны участники,
согласие и период наблюдения. Точные действия и готовые материалы — в таблице P1.

Разработку можно продолжать по воспроизводимым ошибкам и результатам этих
проверок. После предоставления доступа или решения агент выполняет техническую
часть без повторного согласования уже разрешённой работы. Новый технический
срез сам по себе не закрывает ни одно из шести условий.
