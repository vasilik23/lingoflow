## Что готово

`ops/performance-probe.mjs` делает ограниченную серию последовательных GET.
CLI проверяет только фиксированные публичные `/start/`, `/login/`, `/sources/`;
другой URL, POST, cookies или автоматический вход в CLI не поддерживаются.
Библиотечный режим с доверенным адаптером существующей QA-сессии проверяет
только `/`, `/course/`, `/reading/`. По умолчанию 3 запроса на маршрут,
допустимо 2–10, без повторов ошибок; таймаут запроса 15 секунд.

Отчёт содержит SHA, источник `operator_supplied`, контекст, время начала/конца,
группу маршрута, количества успешных/ошибочных ответов, nearest-rank p50 и
p95. Для чётного числа значений p50 — порядковая статистика, не среднее двух
центральных значений. Отдельно показаны первый и последующие запросы: это **не доказательство**
холодной или прогретой serverless-инстанции.

- `headers_ms`: время до получения заголовков, включая сеть и клиентский адаптер.
- `total_ms`: до чтения тела; данные тела не декодируются и не сохраняются.
- `app_ms`: метрика `app` из существующего `Server-Timing`, не вся сеть/edge.
- Задержки считаются только по HTTP 200; редиректы, 4xx, 5xx и transport-сбои
  остаются в отдельных счётчиках. Неизвестный `app` — `null`, не 0.
- Не сохраняются URL/query, cookie, request ID, email, пользовательские тексты
  или содержимое ошибок. Тело ограничено 5 MiB, редиректы не выполняются.
- Выходной файл эксклюзивный `0600`, родительский каталог `0700` вне Git.
  Вывод CLI — только успешность записи и количество попыток.

```sh
mkdir -m 700 /private/tmp/lf-performance-example
node ops/performance-probe.mjs FULL_PRODUCTION_SHA /private/tmp/lf-performance-example/public.json
node --test ops/performance-probe.test.mjs
```

Перед запуском и после него сверить точный deployment и SHA canonical domain.
Инструмент не выдаёт переданный оператором SHA за криптографически проверенный.
При смене production в середине замера отчёт не использовать для сравнения.
Один каталог/файл на новый запуск; пример повторно не перезаписывает отчёт.

### Лабораторная загрузка публичной страницы

Chromium 145, `/start/`, 390×844, device scale 3, CPU slowdown 4×,
сеть 1,5 Мбит/с вниз, 0,75 Мбит/с вверх, latency 120 мс. По 3 последовательные

Первый harness читал метрики до завершения load/отрисовки и получил отсутствующий
LCP и DOM interactive=0: та серия **исключена**, а не объявлена быстрой загрузкой.
После исправления выполнены 9 новых загрузок. Итоговые агрегаты:
`/tmp/lf-render-baseline.json`. Большая задержка PL/EN совпадает с существенно
большим объёмом блокирующего JS; тексты/раскладка языков также различаются,
поэтому это кандидат на проверку причинности, не доказательство вклада одного файла.

Отложенная загрузка требует учесть inline-скрипты упражнений: они уже обращаются
к `PolskiFlowI18n`, поэтому механическое добавление `defer` может сломать
переводы. Сначала — лабораторный срез загрузки RU/PL/EN, затем изолированное
изменение порядка/объёма с проверкой переводов, упражнений и аудио и замером
до/после на одинаковом стенде. Beta-версию этим срезом не меняем.

## Граница с полной beta

Это собственные операторские запросы, не трафик согласившихся участников:
`field_metrics=false`, `beta_readiness_evidence=false`. Они не дают 500 запросов
когорты, 50 попыток, подтверждённых потерь/дублей, недельного p95 или INP.
Отдельные p95 нельзя усреднить в общий p95.

Для следующего согласования предложен минимальный сбор: фиксированная группа
маршрута, HTTP status, длительность и SHA; для учебных попыток — серверно
подтверждённые начало/сохранение с идемпотентным учётом. Нужны определённая
когорта, окно, исключение операторских/бот-запросов и проверка целостности
попыток. Только runtime-логов Hobby за 1 час для полной beta недостаточно.
До реализации/согласования источника, состава, доступа и срока хранения
**никакая новая аналитика не включается**, неизвестные значения остаются null.

Проверки: 1184 Django-теста, system check и migration drift; 62 Node-теста,
из них 10 новых в performance probe. Node ops suite
включает тесты вычисления p95, неизвестных значений, ошибок/редиректов,
последовательности/allowlist, редактирования приватных полей и записи файлов.
Итоговые количества и CI фиксируются в draft PR. Новая миграция не требуется.
