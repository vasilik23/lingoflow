# Напоминание на открытой странице «Сегодня»

Реализован foreground-канал web RU/PL/EN. Он не доставляет системные push,
email или уведомления в закрытое приложение. Native API сохраняет
`delivery_active=false`: фоновой доставки для мобильного клиента нет.

## Включение и отключение

1. В системных настройках сохранить «Напоминать о занятиях каждый день»
   и время Europe/Warsaw.
2. Нажать «Включить на этом устройстве». Это отдельный opt-in для
   текущего аккаунта и браузера, без системного запроса разрешений.
3. После выбранного времени открыть «Сегодня» или оставить её видимой.
   Одно компактное напоминание появится над планом. «Понятно» его скрывает.
4. Отключить на устройстве либо снять ежедневное напоминание и сохранить:
   серверный отказ распространяется на устройства при следующей проверке.

Проверка идёт при открытии, возвращении на страницу и раз в минуту, только
пока «Сегодня» видима и устройство включено. При скрытии вкладки карточка
убирается. Во время урока/экзамена планировщик не загружается. После
выбранного времени можно получить напоминание до конца того же дня;
накопления пропущенных дней нет. Показ не зависит от выполнения дневного
плана и не меняет учебный прогресс.

## Защита и ограничения

- `GET /session/reminder/` использует только текущую cookie-сессию;
  Authorization запрещён, токены не попадают в JS. `private, no-store`.
- Каждый запрос заново читает owner-scoped предпочтения через существующий
  Data API/RLS. Ошибка, неверное время или timezone означают отказ от показа.
- День и наступление времени рассчитывает сервер, включая DST Warsaw.
- Ответ другого аккаунта, ответ старше 5 секунд, уход со страницы,
  отказ сети или недоступное хранилище не дают показ.
- Web Locks сериализует проверку и запись даты между вкладками. Если Web
  Locks отсутствует, канал недоступен; это отражено в настройках.
- `localStorage[lingoflow-reminder:<salted namespace>]` содержит только
  `enabled` и последний `day`. Последний день заменяется, история не растёт.
  Ключ отделён для аккаунтов, не содержит email, токенов или ответов.
  Выход не очищает предпочтение; удалить его можно очисткой данных сайта.
  Очистка снимает opt-in. После повторного включения возможен новый показ
  в тот же день. Между разными браузерами устройства не дедуплицируются.
- Нет Service Worker background-таймера и автоматического permission prompt.
  Смена серверного согласия может скрыть уже видимую карточку с задержкой
  до следующего запроса; чтение согласия и локальный показ не атомарны.
- Схема, grants и RLS не меняются; новых серверных данных не записывается.

## Проверка 16 октября 2026

Изолированные Django-тесты проверяют свежее согласие, owner, cookie-only,
ошибки данных, границу времени и смену DST. Node исполняет настоящий JS:
opt-in, повторный показ, отказ хранилища/сети, чужой owner, устаревший ответ,
скрытие, уход и очистка хранилища. Chromium: настройки RU/PL/EN на
320/390/1440 px, две настоящие вкладки с Web Locks (ровно одна карточка),
refresh, клавиатурное закрытие, отозванное согласие, offline и чужой owner.
Preferences в браузерной проверке подменены; данные пользователей не менялись.
Это не приёмка нового канала на физическом iPhone и не проверка push.

Основание границ платформы:
[WebKit: Web Push on iOS](https://webkit.org/blog/13878/),
[MDN: Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API).

Полный release baseline: 1081 Django-тест, `check`, migration drift и
`git diff --check` пройдены. Изменения базы не требуются.
