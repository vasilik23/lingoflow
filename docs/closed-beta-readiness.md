# Критерии закрытой beta

Подготовлена локальная команда `beta_readiness`: она оценивает агрегированный
отчёт, не собирает telemetry, не обращается к Supabase/Groq и не публикует
приложение. Участники beta и реальные наблюдения этим этапом не подменяются.

## Первоначальная политика closed-beta-v1

Это рабочие пороги владельца продукта для закрытой beta, а не доказательство
качества обучения, статистической достоверности или соответствия CEFR.
Их следует пересмотреть по результатам beta явным изменением политики.

| Проверка | Критерий |
| --- | --- |
| Версия | Отчёт относится к полному Git SHA проверяемой версии |
| Период | Не менее 7 календарных дней, конец периода не старше 7 дней |
| Участники | Не менее 20 согласившихся участников, посчитанных без дублей |
| Учебный путь | Не менее 50 начатых попыток Today → lesson → result |
| Завершение | Не менее 95% начатых попыток завершены и результат подтверждён хранилищем |
| Целостность | 0 попыток с потерянным результатом, 0 попыток с дублем сохранённого результата |
| Сервер | Не менее 500 запросов учебного пути; доля HTTP 5xx не выше 0,5% |
| Задержка | p95 ответа для тех же запросов не выше 2000 мс |
| Обратная связь | 0 открытых blocking и high проблем по итогам triage |
| Ручная приёмка | Подтверждены Safari iPhone/Mac audio, восстановление пароля, удаление аккаунта, AT-аудит, privacy и независимая проверка контента |

Период и агрегаты должны описывать одну версию и одну когорту; даты включаются
в период с обеих сторон. Участников считать уникально в источнике, не помещая
их идентификаторы в итоговый JSON. Счётчики `lost_results`/`duplicate_results`
считают затронутые попытки, а не количество сообщений об ошибке.
`completed` означает подтверждённый сохранённый результат, не показанный экран
успеха. p95 округлять вверх до целых миллисекунд и вычислять по всей выборке,
не усреднять отдельные p95. Latency ответа не заменяет field INP; автоматически
INP или согласие пользователя этой командой не измеряются.

`manual: true` означает фактическую приёмку этой версии на соответствующем
устройстве/сценарии и отдельную запись доказательств в согласованном закрытом
месте. `false` — найденную незакрытую проблему, `null` — проверка ещё не проведена.
Реальный Safari/VoiceOver нельзя заменить DOM-тестами. Юридические данные и
retention должен утвердить владелец; технический отчёт не принимает это решение.

## Запуск

1. Скопировать [пустой шаблон](beta-summary.example.json) за пределы Git.
   Не заменять неизвестные значения нулями: неизвестное отмечается `null`.
2. Собрать согласованные наблюдения и заполнить только агрегаты. Полный SHA
   получить через `git rev-parse HEAD`. Не помещать e-mail, имена, ID аккаунта,
   тексты писем/речи, токены или свободный текст замечаний в JSON.
3. Использовать Python проекта из PyCharm. Из `backend/` выполнить:

   ```text
   <PYTHON_PROJECT> manage.py beta_readiness /private/tmp/beta-summary.json --expected-commit FULL_COMMIT_SHA --check
   ```

   `<PYTHON_PROJECT>` заменить executable настроенного интерпретатора,
   `FULL_COMMIT_SHA` — полным SHA проверяемого релиза. Отчёт выводится в stdout.
   При необходимости перенаправить его в локальный файл вне Git.
4. Разобрать результаты по `checks`. `--check` возвращает ненулевой exit code
   при `blocked` или `insufficient_data`; без этого флага выводится тот же отчёт.
5. Исправить блокеры и заново собрать достаточные актуальные наблюдения.
   Решение о широком запуске принимать отдельно, с учётом всех launch blockers.

`checks_passed` означает выполнение этой предварительной политики по данным
оператора. `release_authorized` всегда false: команда не проверяет происхождение
цифр, не заменяет экспертов и не разрешает выпуск. Пустой шаблон возвращает
`insufficient_data`. Найденная проблема даёт `blocked`, даже если одновременно
недостаточно участников. Несоответствие целевого коммита тоже блокирует проверку.

Неизвестные/повторные поля, bool вместо счётчика, противоречивые количества,
будущие даты и файл больше 16 KiB отклоняются без вывода исходного содержимого.
Перед запуском реальной beta получить согласие и согласовать способ сбора
данных; эта команда не добавляет новую аналитику или хранение в приложение.
