## Исправление генератора

Прежний общий preview сворачивал теорию в одно объяснение и общий источник,
пересоздавал вопросы и связи карточек. Для принятой существующей темы это
не позволяло гарантировать сохранность формата и идентификаторов.

Добавлены необязательные поля manifest v1: grammar.sections (пары heading/text),
card.source_metadata и position, reading.source_metadata и source_glossary.
Последнее хранит прежнее представление глоссария и обязано совпадать с
нормализованным glossary по формам и значениям. Per-object metadata разрешены
только для собственного original-контента с валидными created_for/verified_at;
проверка внешнего источника не обходится.

Оба генератора сохраняют существующие ID вопросов по lesson/position;
лишние позиции деактивируются, не удаляются. Неизменившиеся связи карточек
не пересоздаются. Для summary-only manifest генерируется реальный формат
теории — пара заголовок/текст. Старые manifest без расширений поддерживаются;
checksum по-прежнему связывает все новые поля с review.

- Штатный receipt создан и проверен по checksum всех трёх preview-файлов.
  Его reviewer_boundary.approved остаётся false; это проверяемая подготовка,
  не запись о выполненном production promotion.
- SQLite: два выполнения кандидата в транзакции, все значения и primary keys
  сохранены, транзакция откатилась.
- PostgreSQL: отдельно проверены копия из seeds и локальная копия фактических
  production-строк. Два выполнения сохраняют содержимое и ID. Принудительный
  отказ после изменения заголовка полностью откатил транзакцию.
- Расширенная read-only сверка нашла отличающиеся ID некоторых вопросов между
  seeds и production и два отличающихся описания соседних reading-check уроков.
  Эти поля не подменяются: тест production-копии подтверждает сохранность
  фактических значений. Новых learner-записей не читали и не создавали.
- 27 тестов workflow, полный набор 1230 Django и 77 ops, system check,
  migration drift и diff check прошли. Три новых регрессионных сценария
  проверяют сохранение значений/ID, повторное выполнение, корректный формат
  теории и отказ на некорректных расширениях.

## Delta и откат

В проверяемом content delta: **0 созданных, 0 изменённых, 0 удалённых строк**
по конечным значениям. Кандидат может выполнять UPDATE с теми же значениями;
это не обещание отсутствия SQL-операций или расхода sequence при применении.
Тема уже есть в production, переписывать её ради нулевого повторного выпуска
не требуется. Производственные миграции и регистрация promotion не выполнялись.

Для нулевого delta восстановление контента не нужно. План запрещает отключать
прежнюю A1 как «новую тему». Полный before-snapshot и его SHA-256 лежат в
release-plan.json; при любом drift перед будущим применением остановиться и
подготовить новый reviewed forward-only corrective preview. Рабочие migration
catalogs, production-данные и RLS/grants в этой работе не менялись.
