# Реальные данные для retention-проверки · 23 октября 2026

## Реализовано

- `profiles.last_request_at` и `activity_tracking_started_at`: время базы,
  без URL, текстов, IP или токенов. Web-cookie и native Bearer проходят одну
  точку учёта в SupabaseAuthMiddleware. Гости, static/admin и health/readiness
  не записываются.
- Клиент не задаёт время/owner для RPC. SECURITY INVOKER и существующая RLS
  ограничивают запись своим профилем. Профильные INSERT/UPDATE также защищены
  триггером: поддельные timestamps заменяются временем базы, начало наблюдений
  не сбрасывается запросом клиента.
- Клиентский ACK-cache до 15 минут, отдельный in-flight lock и backoff 30 секунд
  после ошибки. Cache, сеть или неподтверждённый ответ не ломают занятия.
  RPC не записывает строку повторно в течение 15 минут даже на разных workers.
  TTL возвращается базой по оставшемуся окну, а не назначается заново вслепую.
  Первый запрос окна добавляет один ограниченный 1 секундой RPC; остальные
  обходятся cache. Это не обещание отсутствия cold-start или сетевой задержки.
- `user_feedback.closed_at`: база фиксирует переход в `resolved`, сохраняет
  дату при обычном редактировании, сбрасывает при повторном открытии. Старые
  resolved-строки остаются с NULL; фиктивной backfill-даты нет. Обычному ученику
  не добавлены права закрывать обращения.
- Метаданные включены в существующие owner-scoped наборы экспорта profile и
  feedback. Версия экспорта 2.3 сохранена: поля добавлены обратно совместимо,
  новых наборов и пользовательских таблиц нет; каскады удаления не менялись.
- `private.retention_review_snapshot()` — операторский SECURITY INVOKER SELECT
  по реальным Auth/profile/feedback без email и текстов. Недоступен anon,
  authenticated и service_role; private schema не открывалась в Data API.
- `ops/retention-live-report.mjs` принимает JSON результата SQL через stdin,
  создаёт snapshot/report исключительно вне Git в приватном каталоге,
  в stdout выводит только агрегаты. Перезапись, shared directory, stale input
  и произвольные SQL-результаты отклоняются.

## Миграции и права

Django state: `0128_live_retention_evidence`.
Supabase: `20261023093355_live_retention_evidence.sql`; файл создан CLI
2.120.0 и синхронизирован с фактической версией применённой миграции.
Миграция применена до выпуска кода. Production-флаг
`ACCOUNT_ACTIVITY_ENABLED=true` подготовлен в Vercel только для production;
по умолчанию и в preview он выключен. Старое приложение флаг игнорирует.

При ревью обнаружены избыточные profile grants, включая TRUNCATE, на который
RLS не распространяется. У anon отозваны все права profiles; у authenticated
остались только SELECT/INSERT/UPDATE с прежними owner policies. DELETE,
TRUNCATE, REFERENCES, TRIGGER отозваны. Серверное удаление аккаунта не менялось.
Read-only проверка после миграции подтвердила RLS обеих таблиц, отсутствие
anon RPC/общего learner inventory и отсутствие TRUNCATE у публичных ролей.

Advisors до/после: без новых findings; остаются прежние 11 INFO для намеренно
закрытых RLS-таблиц без policy и 2 WARN (существующий rate-limit SECURITY
DEFINER RPC и leaked-password protection). Новые функции SECURITY INVOKER.

## Что этим не утверждается

Новая отметка — наблюдение серверного обращения с 15-минутной агрегацией,
не полный журнал использования. Нет исторической backfill, доказательства
работы offline-клиента, отсутствия сбоев или непрерывности наблюдений.
Snapshot оставляет `activity_complete=false`. Недавнее подтверждённое
использование достаточно для статуса active; старые/неизвестные данные
отправляются на ручную проверку, а не в кандидаты на удаление.

Автоматическое удаление, письма, доставка предупреждений, receipt их получения
и purge после restore не включены. Новая телеметрия не выдаётся за согласие
на рассылку или основание удалить существующие аккаунты. H-02 остаётся открытым
для дальнейшего жизненного цикла и юридической приёмки.
