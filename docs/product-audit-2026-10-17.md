## Подтверждение

**PA-08 · P2 · bug · PO / Designer / QA · высокая уверенность.** Гость выбирает
язык на `/start/`, затем открывает `/privacy/` на том же URL. У privacy выбранный
язык сбрасывается на язык закэшированной страницы. На PL/EN это затрудняет
чтение условий обработки данных. Утечка персональных данных этим наблюдением
не установлена.

Повторено на production 17 октября в новом гостевом Chromium-контексте,
390×844, service worker выключен, `Accept-Language: ru` остаётся неизменным.
Последовательность RU → PL → EN → EN → PL → RU:

- `/start/` корректно меняет язык через настоящий переключатель;
- `/privacy/` во всех шести переходах остаётся RU;
- ответ разрешает `public, max-age=300`, `Vary: Accept-Language`, без Cookie;
- в этом повторе заголовок X-Vercel-Cache был MISS; повторные ответы могут
  приходить из браузерного кэша. Сам по себе этот заголовок не доказывает
  повторное обращение к origin. Ранний ежедневный аудит отдельно наблюдал
  CDN HIT на обычном URL и правильный язык при query cache-busting.

**Механизм:** локаль берётся из cookie, а общая политика кэширования этого
не учитывает. Требуется сохранить выбранный язык и персональные элементы
шапки/контролов; разделение только по Accept-Language недостаточно.

## Исправление

Privacy возвращает `private, no-store` независимо от наличия аккаунта и
`Vary: Cookie` вместе с заголовком локали. Старые публичные TTL больше не
публикуются этой view. Страница остаётся доступной без входа. Изменений
переводов, данных, legal policy, авторизации или других cache routes нет.

## Проверки

- Регрессия с включённым Django shared cache: один URL, постоянный
  Accept-Language, RU/PL/EN в обоих направлениях; сверены html lang,
  Content-Language, заголовок страницы, Cache-Control и Vary Cookie.
- Авторизованный EN-вариант сохраняет приватные заголовки и контролы аккаунта.
- Chromium local, 390 и 1440 px: настоящий языковой переключатель, все шесть
  переходов; правильные локали и заголовки, нет overflow и JS-ошибок.
- 1089 Django tests, system check, migration drift и diff check — PASS.

После выпуска необходим короткий production-повтор на том же `/privacy/`
без cache-busting, с прогревом через несколько переходов и новым контекстом.
Это техническая приёмка PA-08, не независимая языковая редактура PA-01/02.
Ранее исправленные PA-06/07 и LC-01/02 не переоткрываются. Мониторинг по
расписанию уже подтверждён отдельно; прежний ежедневный audit не проверял его.

## PA-09: фокус клавиатуры скрывался нижним меню

**Отдельный PO/Designer/QA проход, 17 октября; база**
`81c6a688d656372ece7e4249ad60f3a6b5f5989f`.
**P2 · bug · высокая уверенность.** Локальный Chromium, fixture-аккаунт,
390×664: открыть `/course/` и нажать Tab 14 раз. Фокус попадает на
«Показать уроки»: прямоугольник y=593–611 при верхней границе фиксированной
навигации y≈589. Элемент полностью закрыт меню. Повторено также на ссылке
продолжения курса, дневной цели профиля, варианте ответа quiz и слове reader.
Пользователь может потерять местоположение фокуса, хотя Tab продолжает работать.
Это не keyboard trap и не утверждение о поведении физического Safari.

Сначала проверен чистый CSS scroll-padding: сам по себе проблему не устранил.
После добавления отложенной коррекции первый повтор удерживал старый шаблон
в локальном сервере; после его перезапуска и проверки загрузки нового файла
регрессия выполнена заново. Ошибка harness не считается дефектом приложения.

### Изменение

После native focus-scroll скрипт проверяет положение фокусируемого контрола
главной области и мгновенно поднимает его над фактической границей нижнего
меню с небольшим отступом. Фокус и значения формы не меняются. При смене
фокуса старый callback ничего не делает. Desktop-сайдбар, меню профиля,
гостевые страницы и элементы внутри dialog не прокручиваются этим обработчиком.
Нет новых сетевых запросов, хранилища или отправки данных.

### Проверка и границы

- axe-core 4.10.3: десять локальных экранов × 390/1440 px × light/dark —
  40 сканов с тегами WCAG A/AA, без автоматически найденных нарушений.
  Этот результат получен до исправления: именно ручной Tab-проход обнаружил
  проблему, которую axe в этих состояниях не выявил.
- Клавиатурная регрессия после исправления: курс, настройки, профиль, quiz,
  reader × RU/PL/EN × 390/1440, по 40 Tab; всего 1200 переходов. Проверяются
  фактическое перекрытие фокусируемого элемента и загрузка нового скрипта.
  На mobile используется dark, на desktop — light.
- Node проверяет коррекцию без смены focus, отсутствие лишней прокрутки,
  desktop/dialog/гостевой вариант и устаревший callback.
- Release baseline: 1090 Django-тестов, system check, migration drift и diff check.
- Изолированная SQLite и синтетический Auth, внешние Supabase/Groq отключены.
  Production-данные не меняются. Нет заявлений о результате реального ученика.

Это закрывает обнаруженный дефект, а не весь assistive-technology audit:

по отсутствию ошибок одного инструмента.
