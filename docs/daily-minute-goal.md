# Единая дневная цель

Профиль хранит `daily_goal_minutes`: 10, 15 или 30. Onboarding и профиль
редактируют одно значение; Today отображает его и автоматически подбирает
задания по длительности. Выполненные сегодня задания и обязательное повторение
остаются в плане, поэтому итог может превышать бюджет. Аналитика оценивает
активность по длительности материалов, а не по измеренному времени.

## Совместимость и база

Миграция `20261007194907_profile_daily_goal_minutes.sql` применена 07.10.2026.
Старые цели 1–2 урока перенесены в 10 минут, 3–4 в 15, 5–10 в 30.
Поле NOT NULL, default 15, CHECK (10, 15, 30); шесть профилей имеют допустимые
значения. Существующие owner-scoped RLS и grants не изменены, новых таблиц нет.
Экспорт данных включает новое поле. Старый код может работать с добавленной
колонкой, поэтому откат приложения не требует удаления поля.

API сохраняет deprecated `daily_goal_lessons` для старых клиентов. Новые
клиенты отправляют только минуты. Для новых минут compatibility count равен
2/3/6; старое изменение количества преобразуется в минуты. Явный `?minutes=`
в Today — только просмотр другого плана, без сохранения настройки.

## Проверка

- 870 Django-тестов, system check, migration drift, `git diff --check`.
- Mobile verify: конфигурация Expo и TypeScript; review двух TSX-компонентов.
- Supabase: anon и чужой authenticated пользователь не читают и не изменяют
  профиль; владелец читает и обновляет минуты; 20 отклоняется CHECK. Проверочные
  записи выполнены в транзакции с откатом. Security advisors не обнаружили
  новых замечаний к profiles.
- Локальный браузер: сохранение 30 минут в профиле, единый бюджет web/API,
  onboarding на 320/1440 px. Завершение восьми карточек урока из Today сохраняет
  галочку, счётчик растёт с 0/3 до 1/3, дневной процент с 0 до 33.
  Persistence подменён локальной фикстурой; production-уроки не записывались.
- На 320 px исправлено переполнение текста карточки экзамена.

Подписанный мобильный build и проверка на физических устройствах остаются
отдельным будущим этапом.
