# Предварительный прогон beta · 3–5 человек

**Статус человеческого прогона: пакет готов; участники и начало наблюдения ещё не подтверждены.**
Владелец выбрал начать с 3–5 человек. Цель — выявить затруднения в обычном
учебном маршруте и потери состояния до расширения группы. Это не прохождение
полной [closed-beta-v1](closed-beta-readiness.md) и не оценка учебного эффекта.
Порог 20 участников / 7 дней / 50 попыток / 500 запросов не снижен.

25 октября владелец отдельно поручил прогон с агентами-участниками.
[День 1 трёх агентных ролей A1/A2/B1 завершён](product-audit-2026-10-25.md)
по этой инструкции на разрешённом тестовом аккаунте. Заполнены обезличенные
листы; сохранение после refresh и следующие шаги проверены. Возвращение
26 октября выполнено: вчерашняя история сохранилась, следующие материалы открыты.
[День 2 и ограничения](product-audit-2026-10-26.md). Это агентная симуляция, не подтверждение
участия людей или выполнения требований полной beta; человеческий пакет ниже
сохраняет отдельный статус.

## Что сделать сейчас

| Кто | Действие |
| --- | --- |
| Владелец | Отправить [готовое приглашение и инструкцию](beta-pilot-invitation.md) 3–5 совершеннолетним участникам; желательно охватить A1/A2/B1 и хотя бы один привычный iPhone/Android/десктоп |
| Владелец | Получить добровольное согласие до наблюдения, договориться о первом занятии и возвращении на следующий день. Выбрать удобный личный канал обратной связи, без новой публичной формы |
| Участники | Пользоваться своими аккаунтами: «Сегодня» → урок → объяснение → результат → следующий шаг; на следующий день вернуться |
| Владелец | Записать фактические наблюдения в копии [бланка](beta-pilot-feedback.example.md) вне Git; передавать агенту только очищенные замечания |
| Агент | Разобрать полученные проблемы, воспроизвести, проверить сохранённые результаты в разрешённом объёме, исправить блокеры и подготовить конкретные шаги повторной проверки |

Это организационный запуск: приглашения агент не рассылает, пользователей
не создаёт и реальных участников не заменяет тестовыми аккаунтами.
Отправленное приглашение и согласие участника не отмечаются без подтверждения.

## Версия и сроки

- Предлагаемый объём: одно занятие 10–15 минут и возвращение на следующий день
  на 5 минут; примерно 2–3 дня с момента первой сессии. Это план, не уже начатый
  период. Даты заполняются по факту, задним числом начало не назначается.
- Записать полный Git SHA production в начале каждой сессии. Для стартового
  релиза использовать текущий production SHA: 24 октября владелец разрешил
  обновление до начала наблюдений, выпуск PR #399 заменяет стартовый PR #398;
  подтверждение deployment находится в описании PR. Не выдавать локальный
  HEAD или номер пакета за фактическую production-версию.
- При исправлении приложения пометить следующую сессию новым SHA. Результаты
  разных релизов не объединять в отчёт одной версии. Документальные изменения
  тоже сохраняют прослеживаемость SHA; для итоговой полной beta применяются
  исходные требования к одной версии/когорте.
- Предыдущий фидбэк A1/A2/B1 и редакторские проверки уже Done. Эта небольшая
  группа — новый прогон, не повод повторно открывать прежние замечания.

## Наблюдение и технические показатели

Обычное сохранение учебного прогресса и журналы провайдеров уже существуют.
**Специальная telemetry beta этим пакетом не установлена:** счётчиков
когорты, автоматического p95 за неделю и записи действий участников нет.

Попросить время/часовой пояс проблемы и проверить технические события вскоре
после неё: Vercel Hobby предоставляет runtime-логи за 1 час, Supabase Free —
API/DB logs за 1 день, Auth audit logs за 1 час по проверенной таблице тарифов
([сверка](operator-retention-acceptance-2026-10-23.md)). Отдельный длительный
экспорт не включён. Поэтому исторические 500 запросов и p95 из этого пакета
автоматически не получаются; неизвестные значения остаются неизвестными.

Организатор собирает только согласованные наблюдения, не пароли, токены,
тексты письма/аудио или browser state. Реальные заполненные формы не публикуются
в Git/PR. Участие можно прекратить; вопросы и запросы удаления направляются
на `lingoflow.privacy@gmail.com`. Идентифицирующие материалы остаются у
организатора, а агент получает очищенный фидбэк. Запись экрана/голоса отдельно
не разрешена этим приглашением. Для нового сбора технических данных полной
beta потребуется отдельно описать объём и согласовать способ сбора.

## Когда закончить этот прогон

1. Получены фактические наблюдения от согласившихся 3–5 человек по первому
   занятию и возвращению; непроверенные шаги явно отмечены.
2. Замечания разобраны: воспроизведение, приоритет, исправление либо объяснённое
   решение. Подозрения на потери/дубли проверены в хранилище, а не только по UI.
3. Нет открытых blocking/high проблем в проверенном маршруте. После исправлений
   затронутые шаги повторены участниками; неповторённое не объявляется принятым.
4. Владелец выбирает следующий шаг: дополнительный малый прогон либо расширение
   до полной beta с отдельным согласованным сбором показателей.

Не запускать `beta_readiness` с подставленными 20 участниками или искусственными
счётчиками. Малый прогон не должен проходить пороги полной beta; это ожидаемое
ограничение объёма, а не повод менять валидатор.
