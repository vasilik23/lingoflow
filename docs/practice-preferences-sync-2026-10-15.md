# Темы практики между устройствами · 15.10.2026

Выбор «Не предлагать удалённую и гибридную работу» сохраняется в аккаунте.
Web-профиль, новые варианты B1, рекомендации B2 и мобильный клиент используют
одно предпочтение. Настройка остаётся только в профиле; каталог материалов
доступен полностью, уже начатые попытки сохраняют свой подписанный вариант.

## Контракт и перенос

`profiles.practice_exclude_remote_work` — nullable boolean:

- `null`: пользователь ещё не сохранял выбор в аккаунте. Web продолжает
  читать старую owner-bound cookie; GET не переносит её на сервер.
- `true`: исключить тему из новых рекомендаций.
- `false`: явный сброс, перекрывающий старые cookies на других устройствах.

Последняя подтверждённая запись побеждает. При недоступности сервера web
использует cookie как запасной выбор для рекомендаций, показывает предупреждение
в профиле и блокирует изменение темы до успешной загрузки. Остальные поля
профиля можно сохранить. Если профиль записан, а тема нет, сообщение явно
описывает частичное сохранение; cookie не обновляется.

`GET/HEAD/PATCH /api/v1/me/practice-preferences/` — bearer-only, private/no-store.
PATCH принимает только `{"exclude_remote_work": true}` или `false`, до 128 байт,
с существующим per-user лимитом `profile` до обращения к storage. Нет user_id
в теле, неизвестные поля и неверные типы отклоняются. Недоступность — 503.
Ответ:

```json
{
  "preferences": {"exclude_remote_work": true},
  "configured": true,
  "recommendation": {"screen": "writing", "title": "Письмо"}
}
```

Это содержимое `data` общего API-envelope. Для B2 сервер выбирает поддерживаемый
нативный **навык**, не конкретное задание; при исключении темы не рекомендует
аудирование про гибридную работу. Каталог навыка остаётся доступен целиком.
Для остальных уровней `recommendation: null`: отсутствующий нативный mini-mock
не выдаётся за реализованную функцию. Перезагрузка экрана практики читает
текущий выбор из аккаунта. Открытый экран не подписан на realtime-обновления.

В мобильном профиле отдельная карточка сохраняет тему независимо от общего
профиля/напоминаний. Ошибка загрузки не превращается в редактируемый пустой
выбор; доступны повтор загрузки и честная ошибка записи. Поздние ответы после
размонтирования/смены токена игнорируются.

Предпочтение включено в существующий набор `profile` экспорта 2.2 как
дополнительное поле и удаляется каскадом вместе с профилем. Новых таблиц,
текстов ответов, аудио и привилегий нет. Privacy и пояснения переведены RU/PL/EN.

## База и порядок выпуска

CLI 2.120.0 создал SQL-файл; после `apply_migration` timestamp файла согласован
с фактической записью Supabase `20261015072309 / synced_practice_preferences`.
Django-state migration — `0123`. Совместимое nullable-поле применено до merge:
прежний код его игнорирует, backfill чужих предпочтений не выполнялся.
Откат кода допускает оставить nullable-поле до отдельного решения.

Проверены существующие RLS SELECT/INSERT/UPDATE с `auth.uid() = id` и
UPDATE WITH CHECK. Grants не расширялись. Анонимный запрос к настоящей
QA-строке вернул `[]`; в откатываемой SQL-транзакции роль `authenticated`
с другим subject увидела 0 строк и обновила 0 строк этого профиля.
Security advisors без новых замечаний; прежние предупреждения и ссылки
описаны в [проверке восстановления B1](b1-storage-recovery-2026-10-14.md).
Контракт RLS сверен с
[официальной документацией](https://supabase.com/docs/guides/database/postgres/row-level-security).

## Проверки и границы

- 1065 Django-тестов: unset/reset, owner-scoped HTTP, подтверждение реальной
  обновлённой строки вместо пустого HTTP 200, ошибки, строгий API, bearer,
  лимит до storage, экспорт, старые cookies и сохранение начатого варианта B1.
- System check, migration drift, `git diff --check`; `mobile/npm run verify`
  (конфигурация beta и TypeScript).
- Локальная копия нового Django-кода с настоящим QA-аккаунтом и production
  Supabase: web-save → независимый браузер → bearer GET; bearer reset →
  первый браузер со старой cookie; реальный экспорт с новым полем.
- Chromium: 18 раскладок профиля RU/PL/EN × light/dark × 320/393/1440,
  без горизонтального переполнения, один h1 и одна настройка темы.
- Отказ записи введён только в локальном HTTP-вызове QA: web показал
  частичное сохранение, cookie и серверная тема не изменились, API вернул 503.
  После снятия сбоя повтор сохранил выбор; B2 API выдал допустимый навык.
- QA-профиль восстановлен в B1, исключение `false`; SQL подтвердил прежние
  один B1-прогон и четыре слова. Прочие пользователи не изменялись.

Нативный клиент не собран и не запущен на устройстве этим срезом. Подпись и
acceptance нового build остаются в плане; прежняя пользовательская приёмка
web/Safari не объявляется приёмкой нового нативного кода. Независимая редактура
польских/английских материалов также остаётся отдельным условием.
