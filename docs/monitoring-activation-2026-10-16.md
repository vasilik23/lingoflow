# Авторизованный мониторинг: активация 16 октября 2026

Включён существующий workflow `Production Smoke` на `main` (`75caa0b`).
Расписание `17 */4 * * *` — каждые четыре часа по UTC; GitHub может задерживать
scheduled runs. Постоянные access/refresh tokens не хранятся и не переиспользуются.

## Аккаунт и граница доступа

- Пользователь предоставил постоянный адрес. На нём уже был аккаунт, поэтому
  для мониторинга создан отдельный Gmail plus-alias, доставляемый в тот же ящик.
  Существующий аккаунт не менялся, его пароль и данные не использовались.
- Новый аккаунт прошёл обычную регистрацию и onboarding `/welcome/`.
  Auth-проверка и отдельный SQL подтвердили `authenticated`, `is_anonymous=false`,
  подтверждение email, отсутствие custom privileges и одну строку профиля.
- Нет учебных completions или personal words. Профиль технический, A1/15 минут.
  Временный QA-аккаунт остаётся отдельным и не участвует в расписании.
- Случайный пароль сохранён в игнорируемом локальном файле `0600` и в
  GitHub environment `production-smoke`; в командную строку, Git или отчёты
  значения секретов не передавались.
- Environment допускает ровно ветку `main`, без tag policy. Job дополнительно
  проверяет ref; credentials checkout не сохраняются. Пять secret names и
  включающий repository variable перепроверены после настройки.

## Исправление предыдущей записи

Setup harness ошибочно ожидал `/onboarding/` вместо настоящего `/welcome/`.
Из-за этого успешная регистрация считалась неудачной, а следующий ответ
«already registered» ошибочно трактовался как запрет адреса. Неиспользуемый
аккаунт с reserved-адресом от предыдущей попытки найден и удалён по точному UUID,
времени создания и адресу-шаблону после проверки пустых учебных данных.
Его Auth-сессии также удалены. Не создавались повторные аккаунты на том же адресе
и не ослаблялись настройки Supabase Auth.

## Оставшиеся проверки

- Подтвердить первый запуск с `event=schedule` и обеими успешными частями.
  Ручной запуск не выдаётся за уже произошедший cron event.
- Проверить получение GitHub Actions failure notifications оператором;
  отдельный внешний alert channel ещё не настроен.
- Следовать процедуре ротации пароля и отключения в
  [operations baseline](operations-baseline.md). Для отключения достаточно
  установить `LINGOFLOW_AUTHENTICATED_SMOKE_ENABLED=false`; публичные пробы останутся.
