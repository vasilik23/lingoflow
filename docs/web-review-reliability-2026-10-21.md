# Надёжность веб-повторения словаря · 21 октября 2026

Раньше `dictionary_practice_step` переходил к следующему слову даже при
`review_saved=False`; на последней карточке завершал тренировку и очищал её
состояние. Повтор отправки также мог заново изменить SM‑2.

## Изменения

- Продвижение и итоговая сводка разрешены только после подтверждённой условной
  записи расписания. При сетевом сбое остаются та же карточка, счёт, проверенный
  ответ и снимок для повтора. Typed-ответ не удаляется до ACK.
- Обе фазы формы подписаны: владелец, слово, содержимое вопроса, режим/источник,
  позиция/счёт, фаза и исходный `last_reviewed_at`. Оценку нельзя отправить вместо
  ответа. Повтор старой answer-формы не получает новую версию расписания.
- Используется уже опубликованный conditional PATCH из мобильного среза:
  владелец + ID + прежний timestamp. Вторая вкладка/потерянный ACK не дают
  повторно изменить старую версию. При stale предлагается обновление вместо
  очередной оценки той же формы.
- Ошибка загрузки словаря не показывается как «На сегодня всё». Устаревшая,
  чужая или изменённая форма получает понятное предложение открыть тренировку
  заново. Страницы/фрагменты содержат `private, no-store`.
- Статусы переведены на PL/EN; действуют режимы перевода, леммы и контекста.

## Проверки

- 1149 Django-тестов PASS; system check, migration drift и `git diff --check` PASS.
- Регрессии: неподтверждённая оценка не продвигает карточку/счёт; retry сохраняет
  снимок; stale блокирует повтор; последняя typed-карточка не завершает попытку
  до ACK; подпись, владелец, срок, позиция/счёт и фаза защищены; старая answer-форма
  сохраняет старый snapshot; недоступный словарь не выглядит пустым успехом.
- **54 браузерных маршрута PASS**: Chromium, RU/PL/EN, светлая/тёмная, 320/390/1440 px,
  перевод/лемма/контекст. Проверяются сбой → тот же ответ → повтор → следующая
  карточка; старая форма во второй вкладке → обновление без оценки; завершение
  четырёх слов → один итог и по одному изменению расписания каждого слова;

  не production-словарь пользователя.
- Отдельная регрессия Today: завершён урок текущего плана, он остался в плане с ✓, процент вырос 0 → 100; запись подтверждена в SQLite-фикстуре.
- Схема, grants и RLS не менялись. Повторно используется проверенная в
  [мобильном срезе](mobile-review-reliability-2026-10-21.md) атомарная условная
  запись; [Postgres-проверка](../supabase/tests/sm2_conditional_review.sql) остаётся
  актуальной. Новых production-миграций нет.

## Границы

Это сохранность текущего веб-шага, не offline-очередь и не восстановление всего
прогона после refresh. После перезапуска учитывается актуальное расписание,
но прежний промежуточный счёт не восстанавливается. При потерянном ACK запись
могла примениться: обновление перечитывает данные вместо повторной оценки.
Сохранение итоговой сводки тренировки — отдельная операция; её собственный
сбой по-прежнему обозначается на итоговом экране.

Режим и список слов используют существующую Django-session: переключение
режима/источника в другой вкладке может сделать прежнюю форму устаревшей;
она не применяется молча к другому заданию. Подпись действует 24 часа.

Живой Safari/iPhone и независимая пользовательская приёмка не заявляются.
Legacy native API без `expected_reviewed_at` не менялся; новый native и web
используют защищённые снимки. Условия широкого запуска остаются открытыми.
