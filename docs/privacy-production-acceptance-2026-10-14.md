## Подготовка и границы

Через обычную `/register/` создан отдельный одноразовый ученик с временным
ящиком [Mail.tm](https://mail.tm/), роль `authenticated`, не anonymous.
Синтетические записи вставлены через Data API с токеном самого ученика,
без service-role ключей и прямой записи в Auth. Это fixtures для проверки
очистки и экспорта, а не настоящие учебные достижения.
Постоянный QA-ученик использовался только как контроль сохранности данных.

Пароли/токены не выводились и не попадали в Git. Локальные доказательства
содержали только статусы, UUID тестовой записи и количества, права 600.
После проверки временный ящик и файл его доступов удалены.

## Отказы и старая сессия

- Удаление через браузер без CSRF: 403.
- Удаление через API с неверным паролем: 403; аккаунт сохранился до правильной попытки.
- Прежний токен на API экспорта после удаления: 401.
- Прежний токен на Auth `/user`: 403.
- Refresh прежней сессии: 400; новый password login: 400.
- Прямой Data API со старым JWT: чтение собственного словаря вернуло `[]`,
  попытка создать новое слово заблокирована FK (409).

Это не заявление о криптографической инвалидизации JWT: его подпись может
оставаться действительной до expiry. Проверены отказ приложения/Auth,
невозможность refresh и отсутствие/защита связанных строк.
