# Защита ИИ-письма от повреждённого разбора · 9 ноября 2026

В [сохранённой серии](ai-writing-quality-followup-2026-11-09.md) обнаружены
`zajęciaх` с кириллической конечной буквой в отзыве и полностью польские
отзывы по четырём критериям при выбранном RU. До изменения оба ответа
возвращались как успешный разбор. Это воспроизведено падающими тестами.

В backend после строгой проверки JSON добавлена узкая детерминированная
проверка только ИИ-письма:

- Отзывы по критериям, объяснения и next_step не должны содержать новых слов,
  внутри которых смешаны латиница и кириллица. NFC-нормализация и casefold
  используются только для этой проверки. Если смешанное слово уже есть в
  исходном ученическом тексте, его упоминание разрешено: так не отбрасывается
  исходное написание имени. Цитаты и правки не переписываются.
- Для RU отклоняется ответ, если в совокупности четырёх отзывов по критериям
  есть ASCII-латиница и нет ни одной русской буквы. Это обнаруживает показанный
  полный уход на другой язык, но не отдельное польское предложение внутри
  русского разбора и не гарантирует, что текст по-русски правилен.

При срабатывании не возвращается результат или оценка: API отвечает обычным
503 с существующей подсказкой о сохранённом черновике и самопроверке. Клиент
может сохранить предыдущий успешный разбор по уже реализованному поведению;
новый отклонённый ответ не заменяет его. Повторный вызов провайдера автоматически
не выполняется. Уже потраченная попытка учитывается в общей квоте.

Диагностика содержит только фиксированные `kind=mixed_script` или
`kind=wrong_language`. Отзывы, исходный текст, имя, ключ и ответ провайдера
в лог не попадают. Тест проверяет безопасные сообщения, один вызов провайдера,
один расход квоты и recoverable API-ответ без result.

## Проверенный объём

Воспроизведены все **23** сохранённых ответа baseline v2 через настоящий
review_writing с подменой только HTTP-транспорта. Два ожидаемых ответа
(participation-error/RU и request-error/RU) отклонены. Остальной 21 ответ
проходит узкую защиту с прежним баллом, включая все 11 корректных контролей.
Среди пропущенных ответов остаются известные неверные советы. Прохождение
этого фильтра не является языковой приёмкой.

Отдельно проверены нормальная русская фраза с польским термином, упоминание
исходного смешанного имени и отклонение нового смешанного имени для RU/PL/EN.
Тесты не обращаются к Groq и не меняют production-квоту.

AILIVE-27-03 остаётся открытым: падежные советы, терминология, последовательность
правок и калибровка этим изменением не исправлены. Модель и prompt прежние.
Новых живых запросов не было: QA 10/10 до 10 ноября 14:11:52 Europe/Warsaw.

После восстановления квоты требуется завершить прежний baseline последней
парой request-correct/EN, отдельно записав версию новой защиты. Новый фильтр
может отклонять неоднозначные новые смешанные написания, отсутствующие в
исходном тексте; в этом случае пользователь получает самопроверку без новой
оценки. Техническая защита готова к проверке в потоке, но повышение общего
качества модели на ней не заявляется.

Проверки выпуска: 16 тестов AI-writing, полный набор **1226 Django**,
**77 ops**, system check, migration drift и diff check прошли. Три новых
регрессионных сценария покрывают baseline, исключение для исходного имени
и отказ API без result/автоматического retry. Установленные ограничения
оценены на сохранённых ответах; новый живой Groq-разбор после изменения
ещё не выполнялся.
