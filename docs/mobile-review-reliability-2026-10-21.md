# Надёжность мобильного повторения SM‑2 · 21 октября 2026

Конкретный исправленный дефект в существующем мобильном клиенте: два быстрых
нажатия отправляли две оценки и могли удалить из очереди две карточки. Ошибка
первоначальной загрузки также отображалась вместе с успешным «На сегодня всё».
Пять новых проверок реальных TSX-обработчиков падали до исправления.

## Поведение после исправления

- Синхронная блокировка допускает один запрос оценки. Карточка удаляется из
  очереди только после совпадающего ответа с её ID и выбранной оценкой.
- Ошибка загрузки — отдельное состояние с повтором и выходом. Пустая очередь
  показывается после успешного чтения; число подтверждений растёт только по ACK.
- При потере ответа неизвестно, сохранилась ли оценка. Кнопки оценивания
  блокируются до обновления очереди. Перевод следующей карточки закрыт.
- Старые ответы загрузки/оценки не заменяют очередь после обновления токена
  или закрытия экрана. Смена аккаунта использует существующую keyed-границу App.
- Контент повторения прокручивается; состояния disabled доступны assistive UI.

## Защита записи

Новый клиент передаёт `expected_reviewed_at`: nullable `last_reviewed_at` из
очереди. Сервер сравнивает снимок с текущей записью, затем выполняет один PATCH
с фильтрами владельца, ID и прежнего `last_reviewed_at`, запрашивая
`return=representation`. Пустой ответ → 409; неполный/неподтверждённый → 503.
Время новой версии строго увеличивается даже при совпадении серверных часов.
После потерянного ACK повтор старого снимка не сдвигает расписание ещё раз.

Условие проверяется внутри UPDATE. Поведение конкурирующих UPDATE основано
на [правилах PostgreSQL Read Committed](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-READ-COMMITTED):
WHERE повторно оценивается после изменения строки другой транзакцией.
[Фильтры PATCH](https://docs.postgrest.org/en/stable/references/api/tables_views.html#horizontal-filtering)
остаются внутри существующих RLS и прав пользователя.

Новых таблиц, миграций, grants, RLS, SDK или ключей нет. Формула SM‑2 и даты
назначений не менялись. OpenAPI описывает nullable снимок и ответ 409.

## Границы выпуска

Исходники и backend публикуются вместе; подписанного IPA/APK и проверки
нативного UI на устройстве нет. TSX-harness выполняет обработчики с управляемыми
хуками, не является React Native renderer. Сборка не подтверждает визуальную
приёмку, VoiceOver/TalkBack или физическое устройство.

Старый web и legacy API без `expected_reviewed_at` сохраняют прежний контракт;
защита от повторной записи по снимку относится к новому мобильному потоку.
Прямые самостоятельные изменения личного словаря через Data API не блокируются.
При ошибке нет фоновой очереди отправки и автоматического выбора новой оценки.
Уже начатый сетевой запрос может закончиться после закрытия экрана; его поздний
ответ не меняет UI, а условие записи защищает от повтора прежнего снимка.

При откате backend учитывать новый клиент: ему нужна поддержка поля снимка.
Он не переходит автоматически на незащищённую legacy-отправку.
