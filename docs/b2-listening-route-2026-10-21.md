# Маршрут аудирования B2 · 21 октября 2026

Закрывает оставшийся пункт PO/QA/design-аудита от 20 октября для одного web-маршрута: «Pilotaż pracy hybrydowej».

## Что изменилось

1. Django проверяет три ответа по исходным вариантам формы. Сохраняется отдельная сводка: идентификатор попытки, материал/версия, число правильных ответов, маска ошибок и серверное время. Аудио, транскрипт, свободные тексты и выбранные формулировки не сохраняются.
2. Подписанное состояние связано с владельцем и версией. Повтор той же отправки идемпотентен; другая оценка не перезаписывает готовую попытку. После подтверждения — redirect на результат; refresh читает сводку вместо повторной записи.
3. После ошибки предлагается один существующий урок: уступка и основной вывод → `b2view-grammar`; понимание делового сообщения → `b2prof-quiz`; решения и результаты встречи → `b2prof-grammar`. При нескольких ошибках сначала разбирается первая. На следующий день в «Сегодня» и рекомендации «Практики» предлагается повтор исходного аудирования.
4. Последняя успешная попытка снимает старое назначение. Исключение темы удалённой работы учитывается. Без результатов сохраняется обычная ротация; персонализацией она не называется.
5. Последние 12 сводок доступны в истории отдельно от точности уроков и самооценки карточек; данные включены в экспорт аккаунта. Удаление аккаунта каскадно удаляет сводки.
6. При сбое сохранения остаются выбранные ответы и тот же идентификатор для повтора проверки; показано предупреждение. Без подтверждения не отображаются успех и сохранённое назначение.

Дополнительно воспроизведена потеря мобильного клика: коррекция фокуса могла прокрутить кнопку между pointerdown и pointerup. Теперь она применяется к `:focus-visible`, сохраняя клавиатурную доступность и фокус полей ввода.

## Проверки

- **1136 Django-тестов PASS**, system check, migration drift, `git diff --check` PASS. Новые проверки: все восемь масок ответов, владелец/подпись/истечение срока, пропуски/неизвестные/повторные значения, совпадающий ACK, конфликт, сеть, повтор после сбоя, refresh и чужая сводка, выбор упражнения, следующий день, новый успех и исключённая тема.
- **18 полных Chromium-маршрутов**: RU/PL/EN × обе темы × 320/390/1440 px. Сбой сохранения → повтор с тем же состоянием → результат 2/3 → refresh → упражнение → следующий день → повтор 3/3 → снятие назначения → история → другой пользователь. Нет ошибок JavaScript и горизонтального переполнения.
- Для браузера использованы изолированные SQLite-фикстуры репозитория, не production-данные ученика. В одном маршруте полностью пройдено предложенное упражнение. Отдельно завершён урок текущего дневного плана: после возвращения вырос процент, появился ✓, запись подтверждена в SQLite-фикстуре.
- Реальная клавиатурная проверка: focused-кнопка остаётся над нижней навигацией, Enter/click ведёт к аудированию. Node-регрессия подтверждает отсутствие прокрутки при обычном pointer focus.
- В Postgres применена additive-миграция `20261021075525_b2_listening_attempts.sql` до выпуска кода. Индекс `(user_id, completed_at desc, attempt_id desc)`, RLS, только SELECT и ограниченный INSERT для authenticated; нет доступа anon, UPDATE/DELETE или клиентской записи времени.
- [Транзакционный SQL-тест](../supabase/tests/b2_listening_rls.sql) на настоящем Postgres подтвердил свой INSERT/SELECT, одну запись при повторе, запрет чужой записи/чтения, запрет UPDATE/DELETE, запрет переопределения времени, проверку соответствия балла маске, отсутствие доступа anon и каскад удаления. Вся фикстура, включая Auth-пользователей, откатилась; оставшихся тестовых строк нет.
- Security advisors не указали новую таблицу. Остаются прежние предупреждения: намеренно доступная функция лимитера [SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) и отключённая [проверка скомпрометированных паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Настройки Auth и лимитера не менялись.

## Ограничения и откат

Это один web-маршрут B2, не общая адаптация всех навыков и не новый экзаменационный балл. Нативное API аудирования остаётся без сохранения; подписанная мобильная сборка — отдельный пункт. Другие уровни аудирования сохраняют прежний режим.

При refresh после неподтверждённой отправки ответы могут потеряться: фоновой offline-очереди здесь нет, предупреждение это объясняет. Восстановленный разбор знает правильность каждого ответа, но не точную выбранную неправильную формулировку. Версия материала должна повышаться при изменении его заданий.

Переход календарного дня проверен с управляемыми датами; живой iPhone и независимая пользовательская приёмка не заявляются. Аудиодвижок и опубликованные файлы не менялись.

При откате кода новую таблицу оставить: она совместима со старой версией. Не удалять пользовательские сводки. Локальный Django-model unmanaged отражает внешнюю таблицу; production-DDL хранится в Supabase-миграции.
