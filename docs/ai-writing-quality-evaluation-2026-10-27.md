оригинальных синтетических писем, четыре пары «ошибка / корректный вариант».
Грамматические ожидания сверены агентом с WSJP PAN; независимой редакторской
приёмкой или калибровкой преподавателем это не является.

| Пара | Ожидание | Роль |
| --- | --- | --- |
| class | Присутствие на занятии: `na lekcji`, не `na lekcję` | Регрессия ранее найденной ошибки; короткие тексты по 23 слова |

| request | `proszę o materiały` либо допустимое `proszę o przesłanie materiałów` | Отложенная проверка на новых текстах по 88 слов |

Словарные статьи и схемы управления указаны внутри fixture. Словарные
определения и корпусные цитаты не импортировались. Вывод о падеже в конкретном
письме — применение справочных данных агентом, не заключение внешнего редактора.
Корректные контроли нужны для поиска ложных исправлений; нехватка объёма у
короткого текста не должна превращаться в выдуманную грамматическую ошибку.

## Воспроизводимая проверка

[ops/writing-quality.mjs](../ops/writing-quality.mjs) анализирует сохранённые
ответы локально. Не читает ключи, не вызывает модель, не меняет флаги, квоту
или production-данные. Вход — JSON до 1 МиБ, только синтетические примеры:

```json
{
  "dataset_version": 1,
  "model": "openai/gpt-oss-120b",
  "reasoning_effort": "medium",
  "runs": [{
    "case_id": "class-error",
    "language": "ru",
    "trial": 0,
    "review": {
      "errors": [{
        "quote": "na lekcja",
        "correction": "na lekcji",
        "explanation": "Проверить падеж в конструкции присутствия на занятии."
      }],
      "next_step": "Допишите письмо до объёма задания."
    }
  }]
}
```

Запуск из корня: `node ops/writing-quality.mjs /private/tmp/candidate.json`.
Exit code 0 — все автоматические проверки и 24 пары покрыты; 1 — найдены
замечания либо недостаточно покрытия; 2 — некорректный вход. Даже при 0
`quality_accepted` всегда false: инструмент не является языковым экспертом.

Он отмечает отсутствие обязательной правки, известную неверную замену,
выдуманную цитату, неизменённое исправление и правки в корректном контроле.
Более длинная точная цитата и разрешённые альтернативы принимаются.
Сравнение учитывает границы слов: `w zajęciach` не совпадает с ошибочным
префиксом `w zajęcia`. Повторы одного текста/языка не увеличивают покрытие.
В отчёт попадают ID и категории, а не тексты писем и ответы модели.
Неизвестная переформулировка тоже может быть корректной: отсутствие совпадения
с разрешённой заменой означает необходимость разбора, а не доказанную ошибку.

Флаги нежелательных советов и кириллицы в PL/EN — повод для разбора, а не
автоматическое лингвистическое доказательство: например, модель может
цитировать неверную фразу с отрицанием. Советы, терминология и оценки требуют
содержательной проверки; инструмент не гарантирует обнаружение всех ошибок.

## Фактический результат

Переоценены сохранённые ответы [живого прогона](ai-writing-live-2026-10-27.md),
без повторных запросов к Groq. Старый вариант `low` включает три ответа на две
уникальные пары текст/язык: отмечены неизменённые исправления, а в одном ответе
также неверный падеж. У текущего варианта `medium` три уникальные пары:
RU class-error не проходит ожидаемую правку; PL participation-error проходит
автоматические проверки; EN participation-error получает флаг совета для
ручного разбора. Этот совет ранее был содержательно проверен как сомнительный.

Это сравнение двух совокупностей изменений (инструкция, reasoning и фильтр),
не изолированный эффект reasoning и не сравнение разных моделей. Объём мал,
есть повтор одного текста; общий процент качества по нему не заявляется.

Выполнен **один новый** production-запрос на отложенном корректном контроле
`request-correct`, RU, 88 слов. Промпт/модель перед ним не менялись:
`openai/gpt-oss-120b`, medium, код `958210d` (функциональный код после #415).
HTTP 200 за 4253 мс, 19/20, **0 ошибок**; черновик сохранился. Это успешный
отрицательный контроль, не доказательство отсутствия всех ложных исправлений.

Итого для текущего варианта покрыты **4/24** пары. По автоматическим правилам
проходят PL participation-error и RU request-correct; два остальных требуют
исправления/разбора. AILIVE-27-03 остаётся открыт. Новую модель или настройку
на этой выборке не выбирали, runtime приложения не меняли.
