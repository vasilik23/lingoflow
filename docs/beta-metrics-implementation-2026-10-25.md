# Минимальные метрики beta · реализация 25 октября

Статус: сбор реализован, **выключен по умолчанию**. Участники не зачислены,
ключ сборщика не установлен, production-данные когорты не собирались.
Это не запуск человеческой beta и не подтверждение её порогов.

## Что реализовано

- Middleware принимает только авторизованные Today, web lesson/step и два
  lesson-result API. Нет SDK, новых cookies или сохранения URL/query, IP,
  User-Agent, email, ответов, текста письма и аудио.
- Нужны одновременно `BETA_METRICS_ENABLED=true`, полный release SHA из
  `VERCEL_GIT_COMMIT_SHA`, серверный `BETA_METRICS_SERVICE_KEY` и действующая
  запись оператора в `private.beta_members`. Отсутствие любого условия
  отключает запись. QA/операторские аккаунты в когорту не зачислять.
- Закрытые таблицы с RLS, без learner/anon grants. RPC — SECURITY INVOKER,
  EXECUTE только service_role. Привилегированный ключ не передаётся браузеру.
  Таблицы диагностики не являются Django ORM-моделями; ordered Supabase
  migration — единственный источник их схемы, Django model state не меняется.
- GET резервирует идентификатор, но не считается началом. Refresh и два
  открытых окна одного незавершённого урока одной версии в пределах 12 часов
  используют ту же резервацию. Начало — принятый POST взаимодействия с уроком.
  Идентификатор переносится в подписанном состоянии с привязкой к владельцу.
- Завершение фиксируется отдельно от подтверждения сохранения. Для обычного
  web-урока проверяется durable completion projection с теми же числами;
  после offline retry — immutable result event с владельцем/ID/уроком.
  Завершение A остаётся отдельно от B. Повторный финальный POST получает
  одинаковые event ID и timestamp очереди, а не новый hash на каждый retry.
- Параллельная резервация защищена advisory transaction lock; PK запрещают
  дубли attempts/request delivery. Смена release не объединяет попытки.
- Операторский `private.beta_report(since, until)` выдаёт только агрегаты и
  точные частоты миллисекунд; `manage.py beta_metrics_report --input FILE`
  считает nearest-rank p95 по отдельным cohort/release/route/method/status.
  Ошибки не смешиваются с успешными запросами. Не усредняются готовые p95.

## Границы показателей

Длительность — Django до отправки диагностического RPC. Она включает время
обработки урока и служебных резервирований, но не завершающую доставку метрики,
сеть до браузера, render или INP. End-to-end и field INP остаются null.

Доставка best effort: отказ/таймаут не ломает урок; недоставленные метрики
восстановить по этому сборщику нельзя. Синхронный RPC ограничен таймаутом
1 секунда; включение добавит сетевые обращения, их накладные расходы нужно
измерить на разрешённой тестовой когорте до массового запуска.
Отчёт всегда `beta_readiness_evidence=false`: это наблюдённый серверный срез,
не полная перепись трафика или независимый аудит потерь.

Незавершённая попытка не объявляется потерей. Неподтверждённое завершение
показывается как `pending_confirmation`; `lost_results` и `duplicates` — null,
пока нет отдельной сверки. Подтверждение projection — наблюдение durable строки
в момент приёма, а не новая immutable запись на каждое обычное завершение.
Письмо, экзамены, native lesson flow, чтение и прочие типы попыток этим срезом
не измеряются. Старый signed state без attempt ID продолжает работать, но
не добавляется к учёту попыток. Длительная пауза >12 часов или смена версии
разделяет резервации. До аналитики удержания нужны независимые аккаунты людей.

## Включение — отдельный шаг

1. Владелец согласует источник, состав, срок до 30 дней и способ информирования
   участников/выхода. Наличие кода не означает этого согласования.
2. Настроить ежедневный вызов `select private.beta_purge();` и проверить его
   исполнение. Сейчас расписание **не установлено**; одна функция не гарантирует
   физическое удаление в срок. Очистка не касается учебных результатов.
3. Оператор добавляет только согласившихся участников в `private.beta_members`
   с cohort и expires_at (не позднее 30 дней от enrolled_at). Не публиковать
   UUID/список участников в Git, PR, shell argv или итоговом JSON.
4. Передать ключ только через серверные environment variables; проверить
   release SHA и затем включить флаг. Не использовать привилегированный ключ
   в браузере или для обычных пользовательских repository-запросов.
5. Сверить известный набор разрешённых действий и накладные расходы. Показатели
   этого диагностического набора не включать в человеческую когорту.
6. Выход: удалить membership (каскадом удалятся связанные диагностические
   попытки). Ранее обезличенные request aggregates сохраняются до очистки.
   Полное выключение — false; уже записанное удаляется оператором по регламенту.

Операторский экспорт: выполнить `private.beta_report` под доверенной ролью,
сохранить только возвращённый JSON вне Git в owner-only файл, затем обработать
командой. Файл не должен содержать сырые таблицы или идентификаторы участников.

## Проверки

- Изолированный PostgreSQL 17: миграция, service-only grants/RLS, отсутствие
  записи для неучастника, owner isolation, GET/refresh, A offline → B → поздняя
  immutable запись A, идемпотентность finalization/request delivery и purge.
  Воспроизводимый сценарий: `supabase/tests/beta_metrics.sql`.
- Django: выключенный путь без сети, некорректный SHA, allowlist, отказ
  коллектора, перенос signed ID, старые токены, одинаковый offline payload
  при финальном retry; расчёт p95 и отказ при лишних персональных полях.
- Реальные устройства и пользовательская когорта в этом срезе не запускались.

Итог локальной проверки: **1203 Django tests — PASS**, system check и
migration drift — PASS; **62 Node ops tests — PASS**. Дополнительно 84
фокусных Django-теста — PASS. Два параллельных локальных PostgreSQL-клиента
получили один ID резервации; сценарий SQL завершён rollback без следов fixture.
В CI добавлен отдельный PostgreSQL 17 job, не подключающийся к production.

Совместимая production-миграция применена **до публикации кода**:
`20261025083448_beta_metrics.sql` (имя файла синхронизировано с migration ledger).
Read-only проверка: members/attempts/requests = 0/0/0; learner RPC и anon read
запрещены. Security advisors: новых WARN/ERROR нет; три новых INFO об RLS без
политик ожидаемы для закрытых service-only таблиц (learner grants отсутствуют,
service_role использует свой BYPASSRLS). Прежние предупреждения проекта
не переоткрывались этим срезом.
