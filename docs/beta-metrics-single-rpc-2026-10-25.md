## Изменение

Раньше открытие урока требовало reserve + observe, завершение — finish + observe.
Теперь `beta_collect_request` объединяет операции в одной транзакции и одном
HTTP RPC. Для Today, промежуточных шагов и result API остаётся один RPC.
Выключенный путь не обращается к сборщику.

После первого обычного render измеряется прежняя граница `django_app_before_collector`.
RPC возвращает привязанный к владельцу attempt ID и стабильное время завершения.
При необходимости HTML формы/очереди обновляется до отправки ответа. Первые
headers/cookies сохраняются, Content-Length пересчитывается; CSRF secret
инициализирован первым render. Это ограниченное повторное серверное rendering,
без фонового потока или ненадёжной отправки после завершения serverless invocation.
У успешного завершения без очереди повторный render не нужен.

GET резервирует, но не начинает попытку. Refresh сохраняет незавершённую
резервацию, A и B остаются раздельны. Повтор финального POST получает тот же
ID/UTC timestamp/hash payload. При отказе/неожиданном ответе RPC остаётся обычная
рабочая форма либо исходная очередь; доставка диагностики по-прежнему best effort.
Потери/дубли без независимой сверки не объявляются нулём.

В Supabase добавлен совместимый service-only SECURITY INVOKER RPC;
`20261025091554_beta_collect_request.sql` совпадает с production ledger.
Старые функции сохранены для rollback. Нет новых таблиц, grants ученикам,
SECURITY DEFINER или изменений Django model state. Отказ observe откатывает
резервирование/завершение в той же диагностической транзакции; обычное сохранение
учебного результата от неё не зависит.
