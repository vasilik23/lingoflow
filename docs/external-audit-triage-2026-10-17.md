## RA-01: новая попытка не должна показывать старый разбор

Baseline восстановлен из HEAD-скриптов через локальный Playwright route, без
смены checkout. Изолированный Django, fixture-аккаунт, Chromium 390 px.
ИИ-контролы и JSON провайдера подменены; production AI-флаги не включались,
тексты во внешние сервисы не отправлялись.

Сценарий: начать письмо → ввести синтетический текст → завершить → получить
fixture-разбор → отметить самопроверку → новая попытка → Start.
До исправления редактор пуст, но consent=true, старый result видим и checkbox
самопроверки отмечен. Механизм подтверждён, реальный охват выключенного
production AI-пилота не заявляется.

Программная замена черновиков теперь посылает отдельное событие сброса:
отменяется ожидающий запрос, очищаются разбор/статус и согласие. Новая попытка
и замена текущей попытки из другой вкладки сбрасывают самопроверку. Совпадение
текстов не сохраняет согласие другой попытки. Очистка localStorage из другой
вкладки очищает редакторы и возвращает начальное состояние. Изменение другого
завершённого комплекта не сбрасывает текущую проверку. Кнопка «Новая попытка»
по-прежнему сохраняет старые тексты до явного Start.

Браузерная приёмка прошла для новой попытки, позднего fetch-ответа, намеренно
игнорирующего AbortSignal, второй вкладки с одинаковым текстом/новой попыткой
и очистки хранилища. Node покрывает жизненный цикл, отмену и отсутствие сброса
при изменении другого комплекта. Серверное оценивание и квоты не меняются.

  выполнялась; запрошено разрешение владельца, доставка не подтверждена.
