# Минимальные показатели полной beta · предложение

**[Ограниченный серверный сбор реализован](beta-metrics-implementation-2026-10-25.md), но не включён.** Для малого прогона остаются
согласованные наблюдения. Это конкретный объём следующего технического среза,
который владелец может оценить перед активацией, а не новое условие уже
завершённой приёмки ручного retention-процесса.

| Показатель | Предлагаемый источник | Как не исказить результат |
| --- | --- | --- |
| Количество запросов / 5xx | Серверные счётчики фиксированных групп Today/lesson/result, method, status, release SHA, cohort | Включать только согласившуюся когорту; QA, ботов и операторские прогоны исключать |
| Задержка | Отдельно Django app duration и согласованный end-to-end response source | Не выдавать app duration за сеть, отрисовку или INP; отсутствующий источник — null |
| p95 | Частотная таблица округлённых вверх миллисекунд, отдельная для scope/версии/когорты | Суммировать частоты, а не усреднять p95; ошибки и неизвестное показывать отдельно |
| Начатая попытка | Серверное принятие явного начала с устойчивым attempt ID | GET, refresh и повторная доставка не создают новую попытку |
| Завершение | Подтверждённая durable запись результата, связанная с попыткой | Экран успеха не является подтверждением; повторная доставка идемпотентна |
| Потери / дубли | Сверка попыток с сохранёнными результатами и подтверждёнными сбоями | Брошенный урок не называть потерей; считать затронутые попытки, не сообщения об ошибках |

Технические агрегаты: версия схемы, release SHA, cohort, окно, фиксированная
route group, method/status counters и длительности. Без URL/query, IP,
User-Agent, email, имён, текстов, ответов и аудио. Псевдонимный attempt ID
нужен в отдельном закрытом учёте целостности; в итоговый JSON не попадает.
Изолировать доступ оператором, запретить learner/anon чтение чужих данных.
Новые таблицы потребуют ordered migration, RLS/grants, idempotency и тестов
гонок/повторной доставки; они входят в срез реализации. Ниже сохранён целевой контракт,
а фактический объём и ограничения описаны по ссылке выше.

**Предлагаемый срок диагностики — до 30 дней**, доступ — владелец/назначенный
оператор, очистка по проверенному механизму. Это предложение для новых данных,
не утверждение об уже работающей очистке. Учебный результат продолжает
подчиняться существующей политике аккаунта, его срок этим предложением не меняется.

Перед включением владелец подтверждает состав/источник/срок и способ включения
участника в когорту; участникам объясняются новые наблюдения и выход из пилота.
Регулярный сбор не полагается на часовой runtime-log Hobby. Новые SDK,
платные сервисы, cookies и внешние получатели этим документом не подключаются.

Критерий готовности реализации: цифры сверены на известном наборе попыток,
offline/retry/refresh не создают дублей, отменённые/незавершённые попытки не
объявляются потерей, owner isolation и очистка подтверждены тестами. Пока
этого нет, `beta_readiness` получает только реально известные значения,
остальные — null. Пороги closed-beta-v1 не изменены.
