# Проверка хранилища напоминаний под Web Lock · 9 ноября 2026

При разборе foreground-напоминаний обнаружена запись состояния устройства вне
общей блокировки. controls() читала enabled, затем повторно читала и записывала
объект enabled/day для проверки доступности localStorage. Если другая вкладка
успевала отключить устройство или отметить показ между чтением и записью,
проверка могла вернуть прежнее согласие/день и допустить повторный показ.

Детерминированный тест воспроизвёл потерю нового состояния: прежний код показал
напоминание вместо сохранения opt-out/дневной отметки. После исправления
проверка доступности тоже получает тот же owner-scoped Web Lock, читает свежий
объект внутри него и записывает его, не перенося старый snapshot через границу
блокировки. Пока блокировка занята другой вкладкой, контролы ждут её освобождения.
Если Web Locks нет, выполняется только чтение и интерфейс остаётся недоступным.

Формат и ключ localStorage прежние, новые ключи не добавлены. Defaults, явный
opt-in, владелец, API, период проверки и отказ при недоступном storage сохранены.
Push/фоновые уведомления, запрос системных разрешений и новый серверный сбор
не добавлялись. Согласия и настройки настоящих пользователей не менялись.

## Проверки

Node исполняет настоящий JS. В существующий тест добавлены контролы настройки,
две воспроизводимые перестановки операций (другой opt-out и claim текущего дня),
проверка нахождения всех записей состояния под lock, toggle и отказ записи.
Регрессия сначала падала на прежнем коде, после исправления проходит.

В Chromium использован локальный компонентный стенд и две настоящие вкладки:
первая удерживает Web Lock, вторая загружает модуль с контролами. До освобождения
lock вторая не пишет состояние. После записи первой вкладкой:

- opt-out сохранён; панель скрыта, запросов mock API нет;
- дневной claim сохранён; свежий mock ответ due=true не вызывает повторного
  показа в тот же день;
- pageerror не наблюдались. Проверены настоящий localStorage и native Web Locks;
  сетевой ответ и пользовательские предпочтения моделировались.

Это узкая проверка гонки изменённого компонента, не повторная полная browser
beta и не приёмка на физическом Safari/iPhone. H-11 остаётся открытым.

Полный набор **1230 Django-тестов**, **77 ops**, system check, migration drift и
`git diff --check` прошли. Проверка JS входит в существующий Django regression
runner, поэтому число Django test methods не увеличилось. Новых вызовов Groq,
изменений Supabase, RLS/grants, формата данных и миграций нет.
