# Языки интерфейса PolskiFlow

Приложение поддерживает русский (`ru`) и польский (`pl`) интерфейсы.
Форма **Язык интерфейса / Język interfejsu** доступна гостю и после входа.
Выбор сохраняется в HttpOnly cookie этого браузера на один год. Если выбора
нет, Django учитывает `Accept-Language`; русский служит запасным языком.
Переключение возвращает на ту же страницу с её фильтрами и параметрами.

Переведены навигация, формы и ошибки, доступные подписи, статусы JavaScript,
таймеры, профиль, материалы, диагностика, B1-режимы, публичные страницы,
каталог тем/уроков, manifest и offline-экран. Поиск курса и общий поиск
учитывают польские названия и исходные метаданные.

Исходные данные курса не переписываются. Польские задания остаются польскими;
русские словарные переводы, учебные пояснения в содержимом уроков и явно
обозначенное пояснение «по-русски» сохраняют своё учебное назначение.
Имена пользователей, личные заметки, названия подборок, сообщения, поисковые
запросы и тексты черновиков не пропускаются через перевод интерфейса.
Прогресс, ответы, идентификаторы и подписанные состояния не зависят от языка.

## Каталог и выпуск

Основной источник — `backend/locale/pl/LC_MESSAGES/django.po`.
Скомпилированный `django.mo` и браузерный `i18n-pl.js` входят в Git,
чтобы production не зависел от наличия GNU gettext на сборочной машине.
`ui_messages.py` содержит маркеры динамических подписей; metadata message IDs
и форматируемые сообщения находятся в `polskiflow/localization/`.

При добавлении текста интерфейса:

1. Пометить статический текст шаблона `{% translate "..." %}`; загрузить
   `i18n ui` до первого использования. Переводить видимые подписи и
   accessibility-атрибуты, не значения форм и не пользовательские данные.
2. Для динамической подписи использовать `ui_text`; для списка перед `join`
   использовать `ui_items`. Новую подпись добавить в маркеры и каталог.
   Сообщения с параметрами использовать с именованными плейсхолдерами.
3. В JavaScript применять `ui('...')` или tagged template `ui` с параметрами,
   добавить исходное сообщение в `browser_messages.json` и gettext-каталог.
4. Заполнить польский перевод, сохранив плейсхолдеры. Для новых метаданных
   каталога обновить `catalog_messages.json`; тест проверяет все выпущенные
   названия и описания тем/уроков.
5. Скомпилировать и собрать браузерный каталог:

   ```bash
   cd backend
   .venv/bin/python manage.py compilemessages -l pl
   .venv/bin/python manage.py build_ui_catalog
   .venv/bin/python manage.py build_ui_catalog --check
   ```

6. Запустить Django tests, system check, migration drift и `git diff --check`.
   Проверить русский и польский интерфейсы в браузере, мобильную ширину,
   переключение посреди прогона и сообщения после действий.

Language POST защищён CSRF; внешний redirect не принимается. Manifest не
кэшируется публично. Service worker и публичный offline shell имеют явный
язык и отдельное имя кэша; ответы аккаунта и API по-прежнему не кэшируются.
Автоматические тесты проверяют соответствие PO/MO/browser-каталогов, наличие
переводов шаблонов и метаданных, параметры, формы числа, безопасное экранирование
и сохранение подписанного прогона при смене языка.
