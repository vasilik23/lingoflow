# Языки PolskiFlow

Django-приложение поддерживает русский (`ru`), польский (`pl`) и английский
(`en`). Выбор языка находится в профиле и формах авторизации. В общей
навигации и меню пользователя переключателя нет. Выбор сохраняется в
HttpOnly cookie на год; без cookie учитывается `Accept-Language`, запасной
язык — русский. POST возвращает на текущую страницу с её параметрами.

Переведены интерфейс, формы и ошибки, accessibility-подписи, JavaScript,
таймеры, метаданные курса, manifest и offline-экран. Поиск курса учитывает
исходные и локализованные названия. Английский также переводит учебные
значения слов, теорию, инструкции, русские формулировки заданий и объяснения
ответов A1–C2. Для 70 учебных чтений добавлены 286 переведённых абзацев:
английский перевод раскрывается отдельно рядом с польским оригиналом.
В экзаменационных заданиях такой перевод текста не появляется.

Польские слова, примеры и оригиналы заданий сохраняются. Порядок вариантов,
ключи ответов, идентификаторы, подписанные состояния и сроки попыток не
меняются. Словарь показывает английский перевод, но сохраняет каноническое
значение из проверенного glossary; переключение не переписывает данные.
Имена, заметки, подборки, сообщения и черновики пользователя не переводятся.
В польском интерфейсе учебные русские переводы продолжают работать как раньше.

Английские переводы подготовлены локально с моделями Argos ru→en и pl→en;
учебные тексты и личные данные внешним сервисам не отправлялись. Выполнены
внутренние исправления интерфейса и грамматической терминологии. Это не
заменяет независимую редакторскую проверку всего английского контента.
[Документация Argos](https://argos-translate.readthedocs.io/en/latest/source/examples.html).
Переводчик не является зависимостью приложения: production читает только
готовые каталоги и JSON, без автоматического перевода во время запроса.

## Каталоги и выпуск

Источники интерфейса — `backend/locale/{pl,en}/LC_MESSAGES/django.po`.
Скомпилированные `.mo` и браузерные `i18n-{pl,en}.js` входят в Git.
`ui_messages.py` и `learning_messages.py` сохраняют динамические message IDs
при gettext extraction; списки выпущенных метаданных и учебных сообщений
находятся в `polskiflow/localization/`. `reading_english.json` содержит
переводы по точному исходному абзацу. При изменении оригинала перевод нужно
обновить: неполная версия не показывается пользователю.

При добавлении материала или интерфейса:

1. Статический интерфейс пометить `{% translate "..." %}`, динамические
   подписи — `ui_text`, списки — `ui_items`. Не применять их к личным данным.
2. Для английского учебного пояснения/значения слова использовать
   `learning_text`: на ru/pl сохраняется оригинал. Польские задания и
   варианты не переписывать и не менять их порядок.
3. В JavaScript использовать `ui(...)` или tagged template с именованными
   параметрами; новые IDs добавить в `browser_messages.json` и каталог.
4. Заполнить pl/en переводы интерфейса и английскую версию нового учебного
   материала. Обновить маркеры и `learning_messages.json`; для чтения —
   точные исходные абзацы и переводы в `reading_english.json`.
5. Собрать и проверить каталоги:

   ```bash
   cd backend
   .venv/bin/python manage.py compilemessages -l pl -l en
   .venv/bin/python manage.py build_ui_catalog
   .venv/bin/python manage.py build_ui_catalog --language=en
   .venv/bin/python manage.py build_ui_catalog --check
   .venv/bin/python manage.py build_ui_catalog --language=en --check
   ```

6. Выполнить Django tests, system check, migration drift и `git diff --check`.
   В браузере проверить desktop/mobile, профиль, урок, перевод чтения,
   словарь, переключение языка и черновик в текущей попытке B1.

Language POST защищён CSRF; внешний redirect не принимается. Manifest
имеет `private, no-store`; service worker и offline shell разделены по языку.
Ответы аккаунта и API не кэшируются. Регрессии проверяют покрытие выпущенных
материалов, параметры сообщений, формы числа, безопасное экранирование,
сохранение канонического glossary и подписанного состояния при смене языка.
