# ИИ-письмо · второй кандидат 22 ноября 2026

Второй кандидат просил модель проверять управление и значение всей фразы:
различать присутствие и направление перед изменением падежа после `na`.
Это следует из статей WSJP PAN о [локализации с местным падежом](https://wsjp.pl/haslo/podglad/23828/na/4012237/na-stole)
и [направлении с винительным](https://wsjp.pl/haslo/podglad/23828/na/4012238/na-stol).
Промпт находился только в защищённом Preview, commit
`8e7d6d03aa410013868da2ea4bc09b4d1b51c74b`, draft [PR #432](https://github.com/vasilik23/lingoflow/pull/432).
Production-промпт не менялся.

Первый синтетический запрос `class-error/RU` вернул HTTP 200 за 2926 мс.
Модель исправила `na lekcja` на **`na lekcji`**, но одновременно объявила
ошибкой корректную просьбу `Proszę przesłać materiały.` и переписала её
как `Proszę o przesłanie materiałów.`. Она утверждала, что предлог `o`
необходим, хотя исходная конструкция с инфинитивом употребляется официальными
польскими организациями, например на [gov.pl](https://www.gov.pl/web/kmpsp-gorzow-wielkopolski/zaswiadczenie-o-zdarzeniu).
Это вывод о ненужной правке по данному контексту и примеру употребления,
не независимая преподавательская оценка. Черновик сохранился.

Парный `class-correct/RU` отправлен один раз и вернул HTTP 503 за 2177 мс;
в приватном runtime-логе зафиксирован `writing_ai_provider_failed kind=http status=400`.
Текст ответа модели отсутствует. Причина HTTP 400 не устанавливается по
безопасным логам без тела провайдера; его нельзя считать лингвистическим
результатом. После двух запросов read-only SQL показал **2/10** попыток QA,
окно началось 22 ноября в 16:39:45 UTC. Повторов, другого аккаунта и
прямых вызовов провайдера не было.

Кандидат остановлен и draft PR закрыт без merge из-за ложной правки в
первом успешном ответе. Ветвевой флаг ИИ выключен, новый Preview READY,
браузерная проверка показала отсутствие кнопки и consent. Старый уникальный
адрес Preview остаётся под Vercel Deployment Protection. Из 24 пар кандидат
дал только один успешный ответ и один сбой; общего показателя качества нет.

Анализатор до этого помечал ложные правки только в полностью корректном
письме. Теперь fixture отдельно отмечает известную корректную фразу внутри
письма с другой ошибкой: если модель цитирует её как ошибку, отчёт получает
`known_correct_phrase_edited_requires_manual_review`. [Безопасный отчёт](ai-writing-context-candidate-result-2026-11-22.json)
содержит ID и категорию без текста письма и модели. Ранее сохранённый полный
baseline v3 воспроизводится без изменения результатов. Проверка — повод для
ручного разбора, а не общий грамматический судья.

Следующий шаг — новая гипотеза с жёстким контролем ложных правок и надёжности
провайдера. Не включать кандидат в Production по одному правильному падежу;
перед полным набором снова проверить ошибочный и корректный контроли.
